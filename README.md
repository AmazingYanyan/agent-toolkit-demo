# AI 与 Agent 技术原理交互式演示平台

面向授信审批部领导与业务人员的本地演示工具。不是把 PPT 搬到网页上，而是**真实调用模型、真实连接 MCP、真实检索知识库**，把抽象概念变成可以看见的执行过程。

一句话主线：**先暴露局限 → 再引入能力 → 运行对比 → 解释原理。**

---

## 快速开始

```bash
npm install
npm run dev        # 开发模式：前端 5173 + 后端 8787
```

正式演示建议用单端口模式：

```bash
npm run build
npm start          # 打开 http://127.0.0.1:8787
```

启动后点击顶栏齿轮，填写模型服务：

| 配置项      | 说明                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------- |
| Base URL | 任何 OpenAI 兼容地址，如 `https://api.deepseek.com/v1`、`https://dashscope.aliyuncs.com/compatible-mode/v1`、内网网关 |
| API Key  | 只写入本地 `data/config.json`，前端永远拿不到明文                                                                      |
| 模型名称     | 必须支持 Function Calling，否则第 4、5 章会失败（失败会如实显示原因，不会伪造成功）                                                    |

也可以用环境变量：`OPENAI_BASE_URL` / `OPENAI_API_KEY` / `OPENAI_MODEL`。

## 三个阶段、十一章内容

| 章节 | 主题                     | 要讲清的一件事                 |
| -- | ---------------------- | ----------------------- |
| 01 | 什么是 LLM                | 模型只看得见你发给它的文字，流畅不等于掌握事实 |
| 02 | Prompt 与 System Prompt | 指令改变「怎么答」，不改变「能拿到什么」    |
| 03 | 上下文与多轮对话               | 模型不记事，记事的是应用            |
| 04 | Function Calling       | 模型提出请求，应用决定执行，工具负责访问数据  |
| 05 | API 与 MCP              | 换的是接入方式，不是模型智力          |
| 06 | RAG                    | 改文档即改依据，参数没有被训练         |
| 07 | Skill                  | 把「怎么分析」沉淀成可复用方法         |
| 08 | 结构化输出与确定性规则 | 结构是约束出来的，判断是程序做出来的 |
| 09 | 什么是 Agent | 给它目标、工具和终止条件，它自己决定下一步 |
| 10 | ReAct | 把「想」和「做」写成文本，让循环看得见 |
| 11 | Plan-and-Execute | 先想清楚整条链路，再按计划执行 |

第 12–14 章（Harness、权限与人工确认、多 Agent）在导航中以「待开放」标出，第三阶段接入。

> 教学目标、观察重点、现场操作顺序与概念解释**不在页面上**，统一放在 [`docs/教学要点.md`](docs/教学要点.md)。页面只保留可操作的控件，讲解材料可单独修改、打印或分发。

## 界面结构

```
┌──────────┬──────────────────────────────┬─────────────┐
│ 章节导航  │ 架构画布（事件驱动，非动画）    │ 运行 / 能力  │
│ 引导/自由 │                              │ 对比 / 详情  │
│          ├──────────────────────────────┤             │
│ 系统自检  │ 执行时间线（真实事件序列）      │             │
└──────────┴──────────────────────────────┴─────────────┘
```

- **架构画布**：节点只在能力启用后出现；运行中按后端事件逐段点亮，运行中有呼吸环，成功打勾，失败变红。接了几台 MCP 服务器，右外列就画几个服务器节点。
- **执行时间线**：`run_started → prompt_built → llm_request_started → tool_call_requested → permission_checked → tool_call_started → tool_call_completed → run_completed`。**点击任意一步，画布会高亮这一步对应的两个节点及其连线**（其余节点变灰），回答「刚才那一步发生在哪里」。**多次对话不会被覆盖**：时间线按「第 1 次 / 第 2 次」分段，每段有自己的颜色，顶部可切「全部 / 只看本次」。
- **工具 Schema 面板**：展示本次真正发出去的 `tools` 数组、完整请求体，以及「工具是随 API 参数发送、不是装进模型」的说明。未运行时按当前配置即时预览。
- **左右两栏可收起**：左上角图标收起章节导航，右上角箭头收起运行面板，中间画布自动铺满；顶栏保留恢复入口。
- **三区可拖拽**：左栏宽度、右栏宽度、下方时间线高度都能拖分隔线调整（双击复位），尺寸记在 localStorage，刷新后保持。投影前按内容调一次即可。
- **回答按 Markdown 渲染**：标题、加粗、列表、表格、代码、引用均正常显示；对比页可点「放大对比」进入全屏投屏视图。
- **前后对比**：同一问题在两种配置下各跑一次，并排看回答、工具次数、耗时与配置差异。
- **详情**：事件 JSON 与业务视图双模式；每次运行保存配置快照（模型、Prompt、工具、知识库版本、MCP 服务器、Embedding 模型）。

## 工具调用 ≠ MCP：两条并列的执行路径

这是本平台最容易被误读的一处，界面上已经写清楚：

```
Function Calling                      MCP
模型怎么提出调用请求                   请求由谁执行
（API 参数 tools + tool_calls）        （标准化的声明与执行协议）
          └──── 互相独立，可单用，也可并用 ────┘
```

同一个「查企业工商信息」的能力，有两种并列的执行路径：

| 路径 | 谁在执行 | 走什么 | 适用 |
|---|---|---|---|
| ① 本地函数直接执行 | 应用进程内的函数 | 不经过网络 | 逻辑简单、数据在应用内、要求低延迟 |
| ② 通过 MCP Server 执行 | 独立进程 / 内网系统 / 云端服务 | JSON-RPC（stdio 或 Streamable HTTP） | 跨团队跨系统复用、外部统一维护与审计 |

模型对这两条路**没有感知**：拿到的都是一份 `tools` 清单，输出的都是一段 `tool_calls`。差别只发生在应用侧。
能力面板里这两组工具是分开列的（① 本地函数 / ② MCP 工具），另有一个「本地演示：同名工具改走 MCP」的对照开关，
用来在画布上直观对比「一跳」与「三跳（工具处理器 → MCP Client → Server）」的区别。

| id        | 服务器              | 传输                          | 协议版本         | 工具数 | 用途                  |
| --------- | ---------------- | --------------------------- | ------------ | --- | ------------------- |
| `demo`    | 演示工商库（本地子进程）     | stdio + 行分隔 JSON-RPC        | `2024-11-05` | 1   | 教学用的虚构企业库，无外部依赖     |
| `ifind`   | 同花顺 iFinD · 证券数据 | Streamable HTTP（POST + SSE） | `2025-06-18` | 9   | 股票摘要、财务指标、EDB 宏观、研报 |
| `kuaicha` | 同花顺 · 快查企业       | Streamable HTTP（POST + SSE） | `2025-06-18` | 2   | 企业工商信息、股权与关联        |
| `law`     | 同花顺 · 法规库        | Streamable HTTP（POST + SSE） | `2025-06-18` | 6   | 法律法规、司法案例检索         |
| `tyc`     | 天眼查 · 企业数据       | Streamable HTTP（POST + SSE） | `2025-06-18` | 17  | 企业搜索、工商画像、股东、风险     |

**合计 35 个真实工具。**

实现要点：

- 手写 JSON-RPC，不套 SDK——目的是让面板里能展示协议原文，而不是一个黑盒方法调用。
- 工具名带命名空间前缀 `服务器id__工具名`（如 `tyc__search_companies`），解决多台服务器工具重名。
- `mcp-session-id` 与 `mcp-protocol-version` 由客户端维护并在每个请求回传；响应同时解析 `application/json` 与 `text/event-stream` 两种形态。
- 单台服务器连不上只会标红该卡片，不影响其它四台，也不阻断本次运行。

密钥从同级目录的 `IFIND密钥.txt` / `天眼查密钥.md` 首次启动时读取并播种进 `data/config.json`，前端只显示脱敏值。也可在 MCP 面板里手工新增、修改、停用、移除服务器。

## RAG：真实的双索引与混合检索

知识库共 **8 篇制度文档 / 61 个分块 / 4719 字**，放在 `server/knowledge/`，改文件即改依据，重启后自动重建索引。

| 文档                            | 内容                          |
| ----------------------------- | --------------------------- |
| `credit-policy-outline.md`    | 对公授信政策要点：总体原则、准入、额度、期限      |
| `financial-analysis-guide.md` | 财务报表分析指引：偿债、盈利、营运、现金流指标口径   |
| `industry-credit-guide.md`    | 重点行业授信关注点：制造、批发零售、建筑、科创     |
| `post-loan-monitoring.md`     | 贷后监控与风险预警处置：十二级分类、预警信号、处置流程 |
| `collateral-guarantee.md`     | 担保与抵质押管理要点：抵押率、保证人、质押登记     |
| `customer-onboarding-dd.md`   | 客户准入与尽职调查清单                 |
| `ledger-operations-faq.md`    | 对公授信业务台账操作问答                |
| `demo-risk-rules.md`          | 教学用虚构规则 R01–R03             |

**两套索引并行**

1. **词法索引**：中文二元组切分 + 倒排表 + BM25 打分。
2. **向量索引**：调 OpenAI 兼容 `/embeddings` 接口，默认 `text-embedding-v4`（1024 维），61 个分块首次入库分 7 批请求，结果按 `hash(model + "::" + text)` 缓存到 `data/index/embeddings.json`，**换模型自动失效重建**。

**三种检索模式**（能力面板可切换，未配置 Embedding 时后两项灰掉）

| 模式           | 公式                      | 说明                      |
| ------------ | ----------------------- | ----------------------- |
| 词法 `lexical` | 归一化 BM25                | 字面命中，术语准确但不懂同义          |
| 向量 `vector`  | 归一化余弦相似度                | 语义召回，能匹配「还不还得起债」↔「偿债能力」 |
| 混合 `hybrid`  | `0.6 × 向量分 + 0.4 × 词法分` | 默认，权重可调                 |

**全链路可视化**：知识库面板按 5 步管道展示——文档入库 → 分块 → 建立索引 → 检索命中 → 注入 Prompt。点任一文档可以看到每个分块的原文、分词结果、向量前 10 维；检索测试会给出**融合分、词法分、向量分与两套排名**的对比表，最后显示真实拼进 Prompt 的那一段文本。

一个实测例子，问「怎么判断一家公司还不还得起债」：

- 仅词法 Top1 = `credit-policy-outline-c1`（总体原则）—— 被「公司」二字带偏
- 仅向量 Top1 = `financial-analysis-guide-c2`（偿债能力指标）—— 语义正确
- 混合：政策原文靠词法排第一（0.866），财务指引靠向量排第三（0.6）

这组对比本身就是第 6 章要讲的「为什么需要两种索引」。

## Skill：一个能力包，而不是一段长 Prompt

`server/skills/financial-risk/` 的结构：

```
SKILL.md                主指令（1306 字）——入口与路由，只写「什么情况下读哪份、跑哪个」
manifest.json           资源清单，同时是「可读 / 可执行」白名单
references/             4 份方法论（合计 3364 字）
  solvency.md             偿债能力
  profitability.md        盈利与收入质量
  cashflow.md             现金流
  indicator-guide.md      指标口径
scripts/                2 个确定性程序（源码合计 6378 字）
  calculate_ratios.py     算指标 + 判阈值
  validate_data.py        校验输入完整性
assets/                 1 个模板（825 字）
  report-template.md      报告输出模板
```

**三层渐进式披露**

| 层 | 内容 | 什么时候进上下文 | 体积 |
|---|---|---|---|
| 1 索引 | 每个 SKILL.md 的文件头（name / description / keywords） | 启动时常驻 | 206 字 |
| 2 主指令 | 命中那一个的 SKILL.md 正文 | 命中才读 | 1306 字 |
| 3 资源与程序 | references / scripts / assets | 模型主动请求才读、才跑 | 全量 10567 字 |

**两个受控工具**（只在 Function Calling 开启且 Skill 命中时提供）

两个工具都要求**同时给出 `skill_id`**：不同 Skill 可能有同名文件，只有 `skill_id + path` 才能唯一定位。
工具仍然只有一个统一入口，归属写在参数里。

- `read_skill_resource({ skill_id, path, reason })` — 只能读该 Skill `manifest.json` 里登记的 reference / asset；
  路径穿越被拒；最多嵌套 2 层（`seeAlso`），单次运行最多 8 份。
- `run_skill_script({ skill_id, script, args })` — 只能执行该 Skill 登记过的脚本；参数按 `args` schema 校验；默认 5 秒超时；
  **无网络访问**、环境变量只给最小集合、无副作用；**脚本源码不进上下文，只回传标准输出**。

**多 Skill 同时加载**

Skill 支持多选，两种选择策略：

| 策略 | 行为 | 用途 |
|---|---|---|
| 自动匹配 `auto` | 在勾选的 Skill 里按问题打分，达到阈值的**全部**加载，可能 0 个 / 1 个 / 多个 | 正常演示：模型自己挑 |
| 全部加载 `all` | 勾选的全部加载主指令，分数只用于展示 | 教学对比：看清「两个主指令同时进上下文」要多花多少字、会不会互相干扰 |

选择阶段会同时报告**跨 Skill 同名资源**与**关键词重叠**。实测两个 Skill 全部加载：主指令 1306 + 999 = 2305 字，
全量预载 17041 字；模型只去读与问题相关的那个 Skill 的资料与脚本，另一个停在主指令层。

实测一次第七章运行：模型先跑 `validate_data.py` 校验输入，再跑 `calculate_ratios.py` 算指标并判阈值，
然后读了 3 份 reference + 1 份 asset，跳过 1 份没读。全量预载 12079 字，实际进上下文 5780 字。
每一次读取、每一次执行都在时间线里留痕，可点开看「哪个 Skill 的哪份资源、参数、输出、还有哪几份没读」。

界面上的能力面板只保留勾选与策略（目录树已挪进「能力包」弹层）；弹层里可以逐个文件查看内容，
还可以用示例参数**真的跑一次脚本**（走的是运行时完全相同的校验与执行链路）。

## 08–11 章：四条控制流

前面七章讲「能力」，这四章讲「谁在控制流程」。同一个模型、同一批工具，换控制流就是换一种系统形态。

| 模式 | 谁决定下一步 | 关键产物 | 真实失败路径 |
|---|---|---|---|
| `structured` | 没有人，只有一次抽取 | 校验通过的 JSON + 规则判定 | Schema 校验不通过 → 只修一次 → 仍不过就停 |
| `agent` | 模型，每轮判断进展 | 每轮决策 JSON（assessment / done / next_action） | 决策格式不合规、工具不在清单、预算耗尽 |
| `react` | 模型，用文本协议 | Thought / Action / Observation 轨迹 | 解析失败、Action 不存在、步数耗尽 |
| `plan` | 规划器决定一次，执行器照做 | 结构化计划 + 执行表 | 计划不合法、工具名编造、参数绑定失败 → 重规划一次 |

**第八章 · 结构化输出**

请求里带 `response_format`（优先 `json_schema`，端点不支持会自动退回 `json_object` 并如实标注），
应用侧用自写校验器逐字段检查类型/必填/枚举/额外字段；不合格带着错误清单重写一次。
通过后交给**确定性规则引擎**算指标、判阈值；最终回答由模板渲染，模型没有直接写结论。

**第九章 · 目标循环**

每轮一次 JSON 决策：`assessment`（现在怎样）、`done`（是否结束）、`next_action`（下一步工具与参数）。
终止条件有三层：模型声明 done、步数预算、连续两次工具失败熔断。界面会区分「目标达成」与「预算耗尽」。

**第十章 · ReAct**

不使用 API 的 `tools` 参数，模型靠文本协议输出 `Thought / Action / Action Input` 或 `Final Answer`；
应用解析后执行，把 `Observation` 拼回对话。解析失败会把原文摊开，再给一次纠正机会。

**第十一章 · Plan-and-Execute**

规划器只出计划（目标 / 理由 / 步骤 / 每步工具与参数 / 期望），应用校验工具名是否真实存在；
执行器按步骤跑，不再问模型「下一步做什么」；某步失败允许**一次重规划**，改的是计划本身；
最后汇总阶段不给工具，模型只能对着观测写结论。

**计划阶段的参数怎么办**：总负债要第 2 步才查得到，所以计划里写占位符
`"numerator": "$2.total_liabilities"`；执行到该步时按字段名去第 2 步的返回结果里取值，
绑定过程会单独出一条事件（原文、绑定值、取值规则）。绑不上就**不执行且标记未解析**，
不塞默认值，避免把计划错误伪装成工具错误。

## 哪些是真的，哪些没做

这是本项目的底线，写清楚以免被误读。

**真实实现**

- 真实调用 OpenAI 兼容接口，SSE 流式；工具调用走标准 `tools` 字段。
- **真实 MCP，5 台服务器 35 个工具**，含 stdio 与 Streamable HTTP 两种传输，协议原文在面板里可查。
- **真实外部数据**：天眼查可查工商信息（实测宁德时代统一社会信用代码 `91350900587527783P`、注册资本 456,360.8365 万人民币、法定代表人曾毓群）；同花顺 iFinD 可查上市公司财务（实测贵州茅台 600519，2024 营业收入 907.03 亿、净利润 460.33 亿）。
- **真实 RAG**：真实 Embedding 调用、真实双索引、真实混合检索，命中片段带来源与三套分数。
- 真实工具执行：查询本地演示库、确定性比率计算、规则引擎判定。
- **真实 Skill 能力包**：索引只读文件头；支持多选与两种选择策略（自动匹配可 0/1/多个、全部加载）；
  `references/` 由模型通过受控工具按需读取，`scripts/` 只回传标准输出、源码不进上下文，`assets/` 按需读取。
  资源与脚本一律带 `skill_id`，多 Skill 同时加载也不会读错文件。白名单、参数校验、超时、无网络全部实际生效，
  越界访问会真实报错。
- **四种真实控制流**（08–11 章）：结构化输出（Schema + 本地校验 + 规则引擎 + 模板渲染）、
  目标循环（每轮 JSON 决策 + 终止条件 + 熔断）、ReAct（文本协议解析 + Observation 回灌）、
  Plan-and-Execute（规划 → 执行 → 一次重规划 → 汇总，含参数占位符绑定）。
  每条失败路径都会真实触发并如实显示，不做静默兜底。
- **真实工具 Schema 展示**：请求体里的 `tools` 数组就是模型看到的东西，面板可直接查看与复制，并能给出「全量 schema 占多少字」。
- **真实多轮时间线**：历次对话的事件全部保留，按对话分段着色，不会被下一轮覆盖。
- 事件协议：`run_id / event_id / sequence / timestamp / event_type / component_id / payload / status`。

**明确未做（不冒充）**

- 权限体系目前是 `default-allow` 并在事件中如实记录策略；分级权限与人工确认属第二阶段。
- 第三方接口的配额用尽会如实报错并显示原始错误码，不做降级伪造。
- 不展示模型内部思维链，只展示模型显式输出的计划与工具请求。
- 第 12–14 章（Harness、权限与人工确认、多 Agent）尚未实现，导航里明确标注「待开放」。

## 接入外部服务需要知道的事

**天眼查**

- 免费档有日/月调用额度上限（正式期 Free 档为 10 次/天、100 次/月；活动推广期可能更高）。额度用尽时服务端返回限流错误，界面会原样显示，不会伪造成功。
- 演示前建议先用「测试」按钮确认配额还在，重要场次不要现场首次调用。

**同花顺 iFinD**

- 三台服务器共用一个 `Authorization` 头，密钥过期需要重新写入 MCP 面板。
- 需要网络能访问 `api-mcp.51ifind.com:8643`（非 443 端口，内网需放行）。

**Embedding**

- 与对话模型共用端点即可，但**模型名必须与服务商实际支持的列表一致**。当前阿里云 MaaS 端点实测 `text-embedding-v3` / `text-embedding-v4` 可用（1024 维），`text-embedding-3-small` 返回 404。
- 首次构建 61 个分块的向量约 7 批请求、几秒钟；之后走本地缓存，换模型或改分块参数才会重建。
- 未配置时检索自动退回纯词法，界面标注为「词法检索」，不会假装做了语义检索。

## 现场演示建议

1. 开场停在第 1 章，什么都不开，先让领导问一句「这家企业注册资本多少」，看模型怎么答。
2. 第 4 章是全场的核心：关工具跑一次、开工具跑一次，**点开工具节点看参数**，再点时间线看「模型请求 → 权限校验 → 工具执行 → 结果回传」。最后打开「完整工具 Schema」面板，指着 `tools` 数组说明它每次都要重新发一遍——工具不是装进模型里的。
3. 第 5 章先打开 MCP 面板给领导看 5 台服务器和 35 个工具，再跑一次天眼查的真实企业查询——**回答里的统一社会信用代码可以当场拿出来核对**，这是「不是假的」最硬的证据。讲这一章要先说清：Function Calling 和 MCP 是两件事，一是模型怎么提请求，二是请求由谁执行。
4. 第 6 章打开知识库面板，先讲 8 篇文档怎么变成 61 个分块，再切「仅词法 / 仅向量 / 混合」跑同一句话，看排名怎么变。
5. 第 7 章先看「能力包」弹层：主指令 1306 字，后面还挂着 4 份资料、2 个脚本、1 个模板。跑一次，让领导看模型自己去读了哪几份、跑了哪个脚本，以及**脚本源码 3917 字为什么一个字都没进上下文**。最后看汇总：全量 12079 字，实际只用了 5780 字。
   再勾上第二个 Skill、切「全部加载」跑一次，看两条「读取主指令」——主指令合计 2305 字，这就是同时加载的代价；模型仍然只去读相关的那个 Skill 的资料。
6. 第 11 章收尾：先看「产出计划」那一屏——计划是可以逐条质疑的；再看「绑定前序结果」，
   讲清「计划阶段不知道值，执行阶段才绑定」；最后看回答由「执行表 + 结论」两部分组成。
7. 收尾用「对比」标签并排两次运行，把「回答更长 ≠ 效果更好」这句话讲透。

## 时间线为什么不再清空

早期版本每次运行都会清空时间线，第二次对话就把第一次的痕迹抹掉了。现在历次运行的事件全部保留，
按 `run_id` 分成「第 N 次对话」，每轮一种颜色（红 → 蓝 → 绿 → 棕 → 紫 → 橙循环），
顶部可切「全部 / 只看本次」。这样做的原因很实在：要讲清多轮上下文，必须能同时看到第一轮与第二轮的请求差异。
