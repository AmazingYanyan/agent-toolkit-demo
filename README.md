# AI 与 Agent 技术原理交互式演示平台

面向授信审批部领导与业务人员的本地演示工具。不是把 PPT 搬到网页上，而是**真实调用模型、真实连接 MCP、真实检索知识库**，把抽象概念变成可以看见的执行过程。

一句话主线：**先暴露局限 → 再引入能力 → 运行对比 → 解释原理。**

---

## 快速开始

```bash
npm install
npm run dev        # 开发模式：前端 5173 + 后端 8787
```

正式演示建议用单端口模式：

```bash
npm run build
npm start          # 打开 http://127.0.0.1:8787
```

启动后点击顶栏齿轮，填写模型服务：

| 配置项 | 说明 |
|---|---|
| Base URL | 任何 OpenAI 兼容地址，如 `https://api.deepseek.com/v1`、`https://dashscope.aliyuncs.com/compatible-mode/v1`、内网网关 |
| API Key | 只写入本地 `data/config.json`，前端永远拿不到明文 |
| 模型名称 | 必须支持 Function Calling，否则第 4、5 章会失败（失败会如实显示原因，不会伪造成功） |

也可以用环境变量：`OPENAI_BASE_URL` / `OPENAI_API_KEY` / `OPENAI_MODEL`。

## 三个阶段、七章内容

| 章节 | 主题 | 要讲清的一件事 |
|---|---|---|
| 01 | 什么是 LLM | 模型只看得见你发给它的文字，流畅不等于掌握事实 |
| 02 | Prompt 与 System Prompt | 指令改变「怎么答」，不改变「能拿到什么」 |
| 03 | 上下文与多轮对话 | 模型不记事，记事的是应用 |
| 04 | Function Calling | 模型提出请求，应用决定执行，工具负责访问数据 |
| 05 | API 与 MCP | 换的是接入方式，不是模型智力 |
| 06 | RAG | 改文档即改依据，参数没有被训练 |
| 07 | Skill | 把「怎么分析」沉淀成可复用方法 |

第 08–14 章（结构化规则、Agent 循环、ReAct、Plan-and-Execute、Harness、权限与人工确认、多 Agent）在导航中以「待开放」标出，第二阶段接入。

> 教学目标、观察重点、现场操作顺序与概念解释**不在页面上**，统一放在 [`docs/教学要点.md`](docs/教学要点.md)。页面只保留可操作的控件，讲解材料可单独修改、打印或分发。

## 界面结构

```
┌──────────┬──────────────────────────────┬─────────────┐
│ 章节导航  │ 架构画布（事件驱动，非动画）    │ 运行 / 能力  │
│ 引导/自由 │                              │ 对比 / 详情  │
│          ├──────────────────────────────┤             │
│ 系统自检  │ 执行时间线（真实事件序列）      │             │
└──────────┴──────────────────────────────┴─────────────┘
```

- **架构画布**：节点只在能力启用后出现；运行中按后端事件逐段点亮，运行中有呼吸环，成功打勾，失败变红。接了几台 MCP 服务器，右外列就画几个服务器节点。
- **执行时间线**：`run_started → prompt_built → llm_request_started → tool_call_requested → permission_checked → tool_call_started → tool_call_completed → run_completed`。**点击任意一步，画布会高亮这一步对应的两个节点及其连线**（其余节点变灰），回答「刚才那一步发生在哪里」。
- **左右两栏可收起**：左上角图标收起章节导航，右上角箭头收起运行面板，中间画布自动铺满；顶栏保留恢复入口。
- **回答按 Markdown 渲染**：标题、加粗、列表、表格、代码、引用均正常显示；对比页可点「放大对比」进入全屏投屏视图。
- **前后对比**：同一问题在两种配置下各跑一次，并排看回答、工具次数、耗时与配置差异。
- **详情**：事件 JSON 与业务视图双模式；每次运行保存配置快照（模型、Prompt、工具、知识库版本、MCP 服务器、Embedding 模型）。

## 五个真实 MCP 服务器

顶栏「MCP」按钮打开服务器面板，可以看到每台服务器的传输方式、协议版本、握手延迟、工具清单，以及**原始 JSON-RPC 往返记录**（`initialize` → `notifications/initialized` → `tools/list` → `tools/call`，含每个请求的 id 与响应）。

| id | 服务器 | 传输 | 协议版本 | 工具数 | 用途 |
|---|---|---|---|---|---|
| `demo` | 演示工商库（本地子进程） | stdio + 行分隔 JSON-RPC | `2024-11-05` | 1 | 教学用的虚构企业库，无外部依赖 |
| `ifind` | 同花顺 iFinD · 证券数据 | Streamable HTTP（POST + SSE） | `2025-06-18` | 9 | 股票摘要、财务指标、EDB 宏观、研报 |
| `kuaicha` | 同花顺 · 快查企业 | Streamable HTTP（POST + SSE） | `2025-06-18` | 2 | 企业工商信息、股权与关联 |
| `law` | 同花顺 · 法规库 | Streamable HTTP（POST + SSE） | `2025-06-18` | 6 | 法律法规、司法案例检索 |
| `tyc` | 天眼查 · 企业数据 | Streamable HTTP（POST + SSE） | `2025-06-18` | 17 | 企业搜索、工商画像、股东、风险 |

**合计 35 个真实工具。**

实现要点：

- 手写 JSON-RPC，不套 SDK——目的是让面板里能展示协议原文，而不是一个黑盒方法调用。
- 工具名带命名空间前缀 `服务器id__工具名`（如 `tyc__search_companies`），解决多台服务器工具重名。
- `mcp-session-id` 与 `mcp-protocol-version` 由客户端维护并在每个请求回传；响应同时解析 `application/json` 与 `text/event-stream` 两种形态。
- 单台服务器连不上只会标红该卡片，不影响其它四台，也不阻断本次运行。

密钥从同级目录的 `IFIND密钥.txt` / `天眼查密钥.md` 首次启动时读取并播种进 `data/config.json`，前端只显示脱敏值。也可在 MCP 面板里手工新增、修改、停用、移除服务器。

## RAG：真实的双索引与混合检索

知识库共 **8 篇制度文档 / 61 个分块 / 4719 字**，放在 `server/knowledge/`，改文件即改依据，重启后自动重建索引。

| 文档 | 内容 |
|---|---|
| `credit-policy-outline.md` | 对公授信政策要点：总体原则、准入、额度、期限 |
| `financial-analysis-guide.md` | 财务报表分析指引：偿债、盈利、营运、现金流指标口径 |
| `industry-credit-guide.md` | 重点行业授信关注点：制造、批发零售、建筑、科创 |
| `post-loan-monitoring.md` | 贷后监控与风险预警处置：十二级分类、预警信号、处置流程 |
| `collateral-guarantee.md` | 担保与抵质押管理要点：抵押率、保证人、质押登记 |
| `customer-onboarding-dd.md` | 客户准入与尽职调查清单 |
| `ledger-operations-faq.md` | 对公授信业务台账操作问答 |
| `demo-risk-rules.md` | 教学用虚构规则 R01–R03 |

**两套索引并行**

1. **词法索引**：中文二元组切分 + 倒排表 + BM25 打分。
2. **向量索引**：调 OpenAI 兼容 `/embeddings` 接口，默认 `text-embedding-v4`（1024 维），61 个分块首次入库分 7 批请求，结果按 `hash(model + "::" + text)` 缓存到 `data/index/embeddings.json`，**换模型自动失效重建**。

**三种检索模式**（能力面板可切换，未配置 Embedding 时后两项灰掉）

| 模式 | 公式 | 说明 |
|---|---|---|
| 词法 `lexical` | 归一化 BM25 | 字面命中，术语准确但不懂同义 |
| 向量 `vector` | 归一化余弦相似度 | 语义召回，能匹配「还不还得起债」↔「偿债能力」 |
| 混合 `hybrid` | `0.6 × 向量分 + 0.4 × 词法分` | 默认，权重可调 |

**全链路可视化**：知识库面板按 5 步管道展示——文档入库 → 分块 → 建立索引 → 检索命中 → 注入 Prompt。点任一文档可以看到每个分块的原文、分词结果、向量前 10 维；检索测试会给出**融合分、词法分、向量分与两套排名**的对比表，最后显示真实拼进 Prompt 的那一段文本。

一个实测例子，问「怎么判断一家公司还不还得起债」：

- 仅词法 Top1 = `credit-policy-outline-c1`（总体原则）—— 被「公司」二字带偏
- 仅向量 Top1 = `financial-analysis-guide-c2`（偿债能力指标）—— 语义正确
- 混合：政策原文靠词法排第一（0.866），财务指引靠向量排第三（0.6）

这组对比本身就是第 6 章要讲的「为什么需要两种索引」。

## 哪些是真的，哪些没做

这是本项目的底线，写清楚以免被误读。

**真实实现**

- 真实调用 OpenAI 兼容接口，SSE 流式；工具调用走标准 `tools` 字段。
- **真实 MCP，5 台服务器 35 个工具**，含 stdio 与 Streamable HTTP 两种传输，协议原文在面板里可查。
- **真实外部数据**：天眼查可查工商信息（实测宁德时代统一社会信用代码 `91350900587527783P`、注册资本 456,360.8365 万人民币、法定代表人曾毓群）；同花顺 iFinD 可查上市公司财务（实测贵州茅台 600519，2024 营业收入 907.03 亿、净利润 460.33 亿）。
- **真实 RAG**：真实 Embedding 调用、真实双索引、真实混合检索，命中片段带来源与三套分数。
- 真实工具执行：查询本地演示库、确定性比率计算、规则引擎判定。
- **真实 Skill 按需加载**：启动只读 `SKILL.md` 的元数据建索引（名称 / 适用说明 / 关键词）；收到问题后用关键词打分匹配，**只有命中才读取正文并注入上下文**，未命中的正文一个字节都不进内存。时间线会依次出现「读取索引」「匹配命中 / 未命中」「按需读取正文」三步，并给出索引字数、命中字数与全量预载字数。
- 事件协议：`run_id / event_id / sequence / timestamp / event_type / component_id / payload / status`。

**明确未做（不冒充）**

- 权限体系目前是 `default-allow` 并在事件中如实记录策略；分级权限与人工确认属第二阶段。
- 第三方接口的配额用尽会如实报错并显示原始错误码，不做降级伪造。
- 不展示模型内部思维链，只展示模型显式输出的计划与工具请求。
- 第 08–14 章尚未实现，导航里明确标注「待开放」。

## 接入外部服务需要知道的事

**天眼查**

- 免费档有日/月调用额度上限（正式期 Free 档为 10 次/天、100 次/月；活动推广期可能更高）。额度用尽时服务端返回限流错误，界面会原样显示，不会伪造成功。
- 演示前建议先用「测试」按钮确认配额还在，重要场次不要现场首次调用。

**同花顺 iFinD**

- 三台服务器共用一个 `Authorization` 头，密钥过期需要重新写入 MCP 面板。
- 需要网络能访问 `api-mcp.51ifind.com:8643`（非 443 端口，内网需放行）。

**Embedding**

- 与对话模型共用端点即可，但**模型名必须与服务商实际支持的列表一致**。当前阿里云 MaaS 端点实测 `text-embedding-v3` / `text-embedding-v4` 可用（1024 维），`text-embedding-3-small` 返回 404。
- 首次构建 61 个分块的向量约 7 批请求、几秒钟；之后走本地缓存，换模型或改分块参数才会重建。
- 未配置时检索自动退回纯词法，界面标注为「词法检索」，不会假装做了语义检索。

## 现场演示建议

1. 开场停在第 1 章，什么都不开，先让领导问一句「这家企业注册资本多少」，看模型怎么答。
2. 第 4 章是全场的核心：关工具跑一次、开工具跑一次，**点开工具节点看参数**，再点时间线看「模型请求 → 权限校验 → 工具执行 → 结果回传」。
3. 第 5 章先打开 MCP 面板给领导看 5 台服务器和 35 个工具，再跑一次天眼查的真实企业查询——**回答里的统一社会信用代码可以当场拿出来核对**，这是「不是假的」最硬的证据。
4. 第 6 章打开知识库面板，先讲 8 篇文档怎么变成 61 个分块，再切「仅词法 / 仅向量 / 混合」跑同一句话，看排名怎么变。
5. 第 7 章先讲「索引只有两百多字，正文八百多字」，再跑两个问题：财务问题看命中和加载，非财务问题看「未命中，不加载正文，省下 1489 字上下文」。这一步最能说明「按需」。
6. 收尾用「对比」标签并排两次运行，把「回答更长 ≠ 效果更好」这句话讲透。
