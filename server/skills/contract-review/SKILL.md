# 合同条款核对 Skill

本文件只是入口。具体条款口径在 `references/`，缺项检查由 `scripts/` 中的脚本完成。

## 一、适用任务

当用户提供合同文本或合同要点，要求核对条款是否齐全、前后是否一致时使用。
本 Skill 只做条款层面的形式核对，不对合同的法律效力、商业合理性作出判断。

## 二、执行步骤

1. **识别合同类型**：采购、服务、租赁或其他；类型不明时先请用户确认。
2. **抽取四类要素**：主体信息（甲方、乙方、统一社会信用代码）、付款节点（比例、时点、条件）、
   违约条款（触发条件、责任方式）、生效条件（签署、盖章、审批）。
3. **缺项检查**：把已识别到的条款编号列表交给 `run_skill_script` 执行
   `check_clause_coverage.py`，由脚本对照必备清单给出缺项，不要凭记忆判断。
4. **读取口径**（按需，不要全读）：
   - 核对担保条款、保证责任 → 读取 `references/guarantee-clauses.md`
   - 遇到特殊约定（排他、自动续期、单方解约）→ 读取 `references/special-terms.md`
   - 需要交付一份可勾选的清单 → 读取 `assets/review-checklist.md`
5. **指出前后矛盾**：例如付款比例合计不等于 100%、生效日期早于签署日期。
6. **按结构输出**（见第四节）。

## 三、数据要求

- 必需：合同正文或条款要点、核对清单。
- 可选：历史同类合同、内部合同模板。
- 缺失正文时，只能核对用户口述的要点，并在结论中说明核对范围有限。

## 四、输出结构

```
一、合同基本信息
（类型、双方、金额、期限）

二、四类要素抽取结果

三、缺失与不一致项
（逐条列出：位置、问题、依据）

四、需业务确认的问题

五、核对范围说明
（本次核对未覆盖的内容）
```

## 五、禁止事项

- 不得对合同的法律效力作出结论。
- 不得替业务部门决定是否签署。
- 不得在缺少正文的情况下声称"已核对全文"。
- 不得把未读取的条款口径写成"已比对制度"。

## 六、语气要求

面向银行业务人员，逐条陈述，不使用"肯定没问题""放心签"一类表述。
